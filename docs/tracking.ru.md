# Трекинг: открытия, клики, отписки

Весь трекинг работает в sendry-web (панели). MTA (`sendry`) не меняется и ничего не знает про трекинг. С MTA общается только панель, поэтому она видит все письма, которые отправила сама: рассылки и письма через API панели (порт 8088).

Если внешняя система вызывает API самого MTA (порт 8080) напрямую, панель этих писем не видит и трекать их не может.

## Что отслеживается

| Событие | Как работает |
|---|---|
| Открытие | В HTML письма вставляется прозрачный пиксель 1x1: `GET /t/o/{token}.gif` |
| Клик | Ссылки в письме заменяются на `GET /t/c/{token}`, панель отвечает 302 на исходный адрес |
| Отписка | Страница `GET /u/{token}` с кнопкой, `POST /u/{token}` для кнопки и для one-click (RFC 8058) |

Публичные адреса работают без авторизации и не проверяются по `server.allowed_ips`. Остальные пути панели защищены как раньше.

Токен подписан HMAC. Исходный адрес ссылки лежит внутри токена, поэтому подменить адрес нельзя и открытого редиректа нет. Домен в токен не входит: ссылки работают через любой домен, который проксирует запросы на панель.

Поведение при неверном токене:

- пиксель всё равно возвращает GIF 1x1 (без записи события), заголовок `Cache-Control: no-store`;
- клик возвращает 404.

## Как включить

### Настройки

**Настройки → Трекинг** (только админ). Значения хранятся в базе, перезапуск не нужен.

| Поле | Описание |
|---|---|
| Проксирующий домен | Домен, через который идут пиксель, клики и отписка, например `lnk.example.com`. Можно без `https://`. Пусто: берётся `server.public_url` |
| Открытия по умолчанию | Включать ли отслеживание открытий в новых кампаниях |
| Клики по умолчанию | То же для кликов |

Если не задан ни проксирующий домен, ни `server.public_url`, трекинг выключен. Письма уходят без пикселя, отслеживаемых ссылок и ссылки отписки.

### Кампания

В форме кампании три опции:

- **Отслеживать открытия**;
- **Отслеживать клики**;
- **Добавлять UTM-метки**.

Значения для новой кампании берутся из настроек. Отписка включена всегда.

UTM-метки добавляются к адресу при редиректе:

| Параметр | Значение |
|---|---|
| `utm_source` | `email` |
| `utm_medium` | `email` |
| `utm_campaign` | название кампании |
| `sc` | ID кампании |
| `sr` | ID получателя в задании (job item) |
| `sl` | номер ссылки |

Параметры, которые уже есть в ссылке, не перезаписываются.

### API-ключ

В форме API-ключа есть флаги `track_opens` и `track_clicks`. По умолчанию они выключены: письма о заказах без пикселя лучше выглядят для спам-фильтров.

### Поля API-запроса

В запросах `POST /api/v1/send` и `POST /api/v1/send/template` API панели можно передать необязательные булевы поля `track_opens` и `track_clicks`. Они перекрывают значения ключа.

```json
{
  "from": "shop@example.com",
  "to": ["client@example.com"],
  "subject": "Ваш заказ",
  "html": "<p>Заказ оформлен. <a href=\"https://shop.example.com/orders/1\">Открыть заказ</a></p>",
  "track_opens": true,
  "track_clicks": false
}
```

Если поле не передано, действует флаг ключа.

Для писем через API отписки в этом этапе нет: ссылка отписки и заголовки `List-Unsubscribe` не добавляются, отписанные адреса не проверяются.

## Отписка

В каждое письмо рассылки панель добавляет заголовки:

```
List-Unsubscribe: <https://lnk.example.com/u/{token}>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```

Gmail и Яндекс показывают по ним свою кнопку «Отписаться».

В шаблоне доступна переменная `{{unsubscribe_url}}`. Поставьте её в футер:

```html
<a href="{{unsubscribe_url}}">Отписаться</a>
```

Если в шаблоне переменной нет, страница запуска рассылки покажет предупреждение.

### Как проходит отписка

1. Читатель открывает `/u/{token}` и видит страницу с адресом и кнопкой «Отписаться».
2. Отписка происходит только после нажатия кнопки (POST). Антивирусы открывают все ссылки в письме, и отписка по самому переходу отписывала бы людей без их ведома.
3. Страница пишет: «Вы отписываетесь от рассылки <отправитель> на адрес <email>». После нажатия показывается «Вы отписались» и ссылка «Вернуть подписку».
4. Запрос one-click от почтового клиента (по `List-Unsubscribe-Post`) отписывает сразу, без страницы.

### Отписка действует в адресной книге

Отписка относится к одной адресной книге: той, в которую было отправлено задание. Читатель получает в этой книге статус `unsubscribed`. Источник истины это статус получателя (`recipients.status`).

- Если тот же адрес есть в другой книге, ему придёт рассылка в эту книгу.
- Повторный импорт CSV в книгу не возвращает подписку.
- Отписанные получатели книги не попадают в задание при запуске. На странице задания это строка «Пропущено (отписаны в этой книге)»: число отписанных получателей книги на момент старта задания.
Отдельного раздела «Отписки» нет. Отписавшиеся адреса видны в адресной книге (`/recipients/{id}`): фильтр по статусу «Отписан» показывает их. Статус можно вернуть в редакторе получателя.

Таблица `unsubscribes` это журнал по паре (книга, email). Решение о рассылке принимается по статусу получателя.

## Карта кликов

Карта есть на странице задания, вкладка **Карта кликов** (только рассылки).

Ссылки нумеруются в исходном тексте шаблона: каждой `<a href>` ставится атрибут `data-sl="N"` до подстановки переменных. Поэтому номер ссылки одинаков у всех получателей, даже при разных данных и условных блоках.

Не отслеживаются:

- `mailto:`, `tel:`, `sms:`;
- якоря `#...`;
- ссылки с атрибутом `data-notrack`;
- ссылка `{{unsubscribe_url}}`.

При старте задания панель сохраняет снимок каждого варианта письма. Если шаблон потом изменят, карта останется верной.

На вкладке:

- снимок письма в `iframe` с бейджами у ссылок: уникальные и всего кликов;
- таблица: подпись элемента, адрес, уникальные клики, всего, доля;
- выбор варианта, если их несколько (A/B).

Ссылки, скрытые условием и не видные в превью, есть только в таблице. Для писем через API карты нет, в карточке письма виден список переходов.

## Метрики

| Метрика | Формула |
|---|---|
| Доставлено | Письма со статусом «доставлено» |
| Открытия уникальные | Получатели, открывшие письмо хотя бы раз |
| Открытия всего | Все открытия |
| Open Rate | уникальные открытия / доставленные |
| Клики уникальные | Получатели, кликнувшие хотя бы раз |
| Клики всего | Все клики |
| CTR | уникальные клики / доставленные |
| CTOR | уникальные клики / уникальные открытия |
| Отписки | Число отписавшихся |
| % отписок | отписки / доставленные |

Метрики показаны на страницах задания и кампании. В списке получателей задания есть колонки «Открыто» и «Клики». В истории API-отправок есть колонка «Открыто», в карточке письма лента событий.

### Машинные события

События сканеров, ботов и клики быстрее 2 секунд после отправки сохраняются с флагом `is_machine` и не учитываются в статистике. Сырые данные не удаляются.

Прокси картинок Gmail и Яндекс считаются настоящими открытиями.

## Ограничения

- Apple Mail Privacy Protection сама загружает картинки, поэтому открытий у получателей Apple Mail больше, чем было на самом деле. Open Rate нужно читать с этой поправкой. Клики этому не подвержены.
- Часть клиентов блокирует картинки. Такие открытия не видны.
- В письме API с несколькими адресатами (`to`, `cc`, `bcc`) один пиксель. Открытие засчитывается письму целиком, а не конкретному получателю.
- Отписки для писем через API пока нет.
- Сырые события хранятся без срока (таблица `email_events`). Срок хранения будет решён позже.
- Разбор User-Agent, GeoIP, графики по часам, жалобы на спам и bounce в этот этап не входят. User-Agent и IP сохраняются.

## Приватность

Трекинг записывает IP-адрес, User-Agent, время и адрес получателя. Это персональные данные. Сообщите о трекинге в политике конфиденциальности и учитывайте местные требования (GDPR и другие). Ссылка отписки должна быть в каждой рассылке.

## Отдельный трекинг-домен (прокладка)

Ссылки в письмах можно отдавать с отдельного домена (например, `lnk.example.com`), а не с домена панели. Если домен попадёт в блок-лист, вы смените его за несколько минут, а сама панель останется закрытой.

Прокладка на nginx пропускает на панель только `/t/` и `/u/`. Всё остальное отвечает 404.

### Пример nginx

```nginx
server {
    listen 80;
    server_name lnk.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name lnk.example.com;

    ssl_certificate     /etc/letsencrypt/live/lnk.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/lnk.example.com/privkey.pem;

    # Только трекинг: открытия, клики, отписка
    location ~ ^/(t|u)/ {
        proxy_pass https://panel.example.com;
        proxy_ssl_server_name on;

        proxy_set_header Host panel.example.com;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header User-Agent $http_user_agent;
    }

    # Всё остальное закрыто
    location / {
        return 404;
    }
}
```

`$remote_addr` здесь IP читателя. Панель берёт его из `X-Real-IP`, затем из `X-Forwarded-For`. Заголовки не проверяются: подделка влияет только на IP в статистике.

### Шаги настройки

1. Создайте A/AAAA запись `lnk.example.com` на сервер прокладки и получите TLS-сертификат (например, через certbot).
2. Положите конфиг выше в nginx и перезагрузите его.
3. В панели откройте **Настройки → Трекинг** и впишите «Проксирующий домен»: `lnk.example.com`.
4. Проверьте: `curl -I https://lnk.example.com/t/o/test.gif` вернёт GIF, а `curl -I https://lnk.example.com/` вернёт 404.

Новые письма получат ссылки на новый домен сразу, перезапуск не нужен.

### Как быстро сменить домен

Если домен заблокировали:

1. Заведите новый домен и прокладку по шагам выше (можно на том же сервере: добавьте ещё один `server_name`).
2. Поменяйте «Проксирующий домен» в настройках.
3. Старый домен не удаляйте, пока не пройдёт время, в которое читатели ещё открывают старые письма. Токены не привязаны к домену, поэтому ссылки в уже отправленных письмах продолжат работать, как только старый домен снова заработает или будет указывать на ту же панель.

Если нужна работа через несколько доменов одновременно, добавьте несколько `server_name` с одним и тем же `location`.
