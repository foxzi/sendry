# План перестройки навигации sendry-web

Статус: черновик, не в работе. Зафиксировано 2026-10-20 по итогам обсуждения UX панели.

## Проблема

Верхнее меню собрано по принципу «по пункту на каждую сущность»: Шаблоны, Получатели,
Кампании, Рассылки, Отправки, Мониторинг, Настройки, Очередь. Восемь пунктов одного веса,
в которых перемешаны задачи маркетолога и администратора.

Конкретные симптомы:

- **Кампании и Рассылки** — одна сущность в двух состояниях (кампания и её запуски),
  но разнесены по двум пунктам меню. Чтобы понять «что с моей рассылкой», нужно ходить
  между разделами.
- **Отправки** — журнал писем, ушедших через API (транзакционные). По смыслу тоже история,
  но из названия это не считывается.
- **Получатели** — внутри это списки, а не люди.
- **Очередь** со счётчиком висит в общем меню рядом с шаблонами, хотя это служебная метрика.
- **Настройки** разбиты на «Инфраструктура» и «Система» по остаточному принципу:
  - глобальные переменные относятся к шаблонам, а не к системе;
  - тестовое письмо — диагностика серверов;
  - DKIM отдельной карточкой, хотя это свойство домена;
  - домены и DKIM существуют в двух версиях: централизованные (`/domains`, `/dkim`)
    и на каждом сервере (`/servers/{name}/domains`, `/servers/{name}/dkim`).
    Пользователь не понимает, где «настоящие»;
  - серверы, очередь, мониторинг, песочница, DNS- и IP-проверки разбросаны между
    Настройками, Мониторингом и пунктом Очередь, хотя это один контур
    «состояние инфраструктуры».

## Целевая структура меню

Шесть пунктов вместо восьми, сгруппированы по задачам.

| Пункт | Что внутри | Сейчас живёт в |
|---|---|---|
| Рассылки | Список кампаний. Внутри карточки кампании — её запуски. Вкладка «История» со всеми запусками | `/campaigns`, `/jobs` |
| Шаблоны | Шаблоны, блоки, медиа, глобальные переменные | `/templates`, `/blocks`, `/media`, `/settings/variables` |
| Аудитория | Списки получателей | `/recipients` |
| Журнал | API-отправки. Опционально вторая вкладка с запусками рассылок | `/sends` |
| Инфраструктура | Серверы, домены (DKIM внутри домена), очередь со счётчиком, мониторинг, песочница, тестовое письмо, проверки DNS и IP | `/servers`, `/domains`, `/dkim`, `/queue`, `/monitoring`, `/settings/test-email`, `/servers/{name}/*` |
| Администрирование | Пользователи, API-ключи, аудит, настройки панели (таймзона и т.п.). Только для админов | `/settings/users`, `/settings/api-keys`, `/settings/audit`, `/settings` |

Счётчик очереди переезжает на пункт «Инфраструктура».

## Открытый вопрос: центральные и серверные домены

Единственное место, где нужно решение по сути, а не по вёрстке. Сейчас есть две
параллельные модели управления доменами и DKIM. Нужно выбрать одну как основную:

- **Вариант А.** Основная модель — централизованная. Серверные домены показываются
  внутри карточки домена как «состояние на серверах» с кнопкой синхронизации.
  Прямое редактирование на сервере остаётся как «переопределение» и подсвечивается.
- **Вариант Б.** Основная модель — серверная. Центральный список — только агрегатор
  для просмотра.

Склоняюсь к варианту А: он соответствует тому, что панель управляет несколькими MTA.

## Порядок работ

Всё, кроме пункта 5, — перестановка ссылок, карточек и вкладок. Адреса страниц и
обработчики не меняются, старые URL продолжают работать.

1. **Меню.** Переименовать и перегруппировать пункты в `internal/web/views/layout.html`,
   обновить переводы в `internal/web/static/js/i18n.js`. Счётчик очереди перенести
   на «Инфраструктура».
2. **Рассылки.** Внутри карточки кампании показать её запуски. Добавить вкладку
   «История» (текущая страница `/jobs`). Пункт «Рассылки» в старом смысле убрать из меню.
3. **Инфраструктура.** Новая обзорная страница вместо карточки «Инфраструктура» в
   настройках: серверы, домены, очередь, мониторинг, тестовое письмо. Из карточки
   сервера оставить ссылки на его очередь, DLQ, песочницу, DNS/IP-проверки.
4. **Администрирование.** Страница `/settings` оставляет только пользователей, ключи,
   аудит и настройки панели. Глобальные переменные переезжают под «Шаблоны».
5. **Домены и DKIM.** Реализовать выбранный вариант из открытого вопроса. Делать
   последним и отдельной веткой.

Шаги 1–4 можно делать по одному, каждый отдельным PR, панель остаётся рабочей
между ними.

## Что сделано в ветке feat/web-sidebar-nav (2026-10-21)

Шаги 1–4 реализованы одной веткой. Шаг 5 (домены и DKIM) не трогали.

Меню переехало влево и сгруппировано по задачам:

- Обзор
- Почта: Рассылки, Шаблоны, Аудитория, Отправки по API
- Система: Инфраструктура (со счётчиком очереди), Администрирование (только админам)

Внутри раздела вкладки в верхней полосе контента:

| Раздел | Вкладки |
|---|---|
| Рассылки | Кампании, Запуски (`/jobs`) |
| Шаблоны | Шаблоны, Блоки, Медиа, Переменные (`/settings/variables`, админам) |
| Инфраструктура | Серверы, Очередь, Домены, DKIM, Мониторинг, Тестовое письмо (админам) |
| Администрирование | Настройки, Пользователи, API-ключи, Журнал аудита |

Отличия от черновика выше:

- Отдельную обзорную страницу инфраструктуры не делали: точка входа — `/servers`,
  остальное — вкладки. Этого достаточно, и нет нового обработчика.
- «Джобы» в интерфейсе называются «Запуски» (Runs). На странице кампании показаны
  её последние запуски, на обзоре — последние запуски по всем кампаниям.
- `/settings` стал страницей «Настройки» внутри Администрирования: таймзона и три
  карточки (пользователи, ключи, аудит). Карточки инфраструктуры оттуда убраны.
- Кнопки «Назад к …» со страниц, которые теперь покрыты вкладками, удалены.

Техника: секция вычисляется из `Active` функцией `navSection` в `views.go`,
вкладки описаны в `layout.html`, переводы `nav.*` и `sub.*` в `i18n.js`.
Адреса и обработчики не менялись.

### Дополнения (тот же день)

- **Переводы.** Все страницы панели переведены на русский через `data-i18n`.
  Словари разбиты по разделам: `static/js/i18n/common.js` (статусы, типы
  ошибок, общие слова), `templates.js`, `campaigns.js`, `infra.js`; они
  подключаются в `layout.html` после `i18n.js` и регистрируются через
  `I18n.register`. Неизвестный ключ оставляет серверный текст как есть, поэтому
  динамические значения можно размечать как `status.{{.Status}}`.
  Не переводятся: имена серверов, адреса, DNS-записи, примеры кода, JSON.
- **Фильтры** на списках применяются сразу при смене значения (селекты) или по
  Enter / уходу из поля (текстовый поиск). Кнопка «Фильтр» скрывается
  скриптом и остаётся только как запасной вариант без JS (`app.js`,
  `initAutoFilters`).
- **Статус и ошибка** в журнале отправок и в элементах запуска разнесены по
  двум колонкам: бейдж статуса отдельно, тип ошибки текстом, полный текст
  ошибки во всплывающей подсказке.
- **Карточки статистики** уменьшены и выровнены по левому краю.
- **Ошибки доставки на странице отправок** показаны двумя кольцевыми графиками
  («Не доставлено» и «Ждут повтора») вместо таблицы: `static/js/delivery-errors.js`
  строит SVG из JSON в шаблоне, цвета закреплены за типами ошибок
  (`--viz-*` в `style.css`, палитра проверена валидатором в обеих темах).
  Легенда со счётчиками остаётся ссылками на фильтр, таблица сохранена в
  `<noscript>` как запасной вариант. Откат: бэкап файлов на момент до графиков
  лежал в scratchpad сессии; в git это один блок в `sends_list.html`, новый JS-файл
  и секция «Delivery error donuts» в конце `style.css`.
