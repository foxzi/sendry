# Маркетинговые рассылки: объём работ по Sendry

Выжимка из «Техническое задание — рассылка.pdf» и «Рассылки — анализ ТЗ и архитектура.pdf».
Здесь только то, что делается в Sendry. Заказы, маржа, сегменты по покупкам, товарная аналитика,
рекомендации и финансовые отчёты остаются на стороне магазина (admin) и сюда не входят.

Граница ответственности: Sendry знает всё про письма и адреса и ничего про деньги.
Стык с магазином — идентификаторы кампании, получателя и ссылки в каждой ссылке письма,
webhook событий наружу и API приёма получателей.

## База подписчиков

- Импорт базы из SendPulse со статусами: активен, отписался, жалоба на спам, ошибка доставки, заблокирован. Дедупликация email.
- Глобальная карточка контакта вместо «получатель в списке»: email, статус, источник, дата добавления.
- Настраиваемые поля карточки: пользователь сам заводит поле с названием и типом (строка, число, дата), значения приходят при импорте или по API. Что именно хранить (город, число заказов и т.п.) решает магазин, Sendry об этом не знает.
- Глобальный список подавления: отписанные, пожаловавшиеся, заблокированные не попадают в новые рассылки, но остаются в базе.
- Приём списка получателей для кампании от магазина по API. Сегмент строит магазин, Sendry получает готовый список.
- История по контакту: полученные письма, открытия, клики, отписки, жалобы, ошибки доставки, почтовый клиент.

## Кампании

- Поля кампании: название, дата и время отправки, тема, прехедер, источник получателей, число адресатов, тело.
- Настраиваемые поля кампании по тому же принципу, что и у карточки. Промокод и период акции из ТЗ заводятся как такие поля магазином, в Sendry они не зашиты.
- Поле прехедера в шаблоне или кампании с автоматической вставкой скрытого блока в HTML.
- Кампании, варианты с весами, планировщик и конструктор уже есть.

## Трекинг

- Лог событий с временными метками: sent, delivered, hard bounce, soft bounce, complaint, open, click, unsubscribe. В событии message_id, campaign_id, recipient_id, link_id, user-agent, IP.
- Пиксель открытий.
- Перезапись всех ссылок письма на редирект с HMAC-токеном. В редиректе на сайт передаются идентификаторы кампании, получателя и ссылки. Дополнительные параметры (например промокод) задаются в самой ссылке шаблона, Sendry их не добавляет.
- Автоматическая идентификация кликабельных элементов письма: логотип, баннер, кнопка, карточка товара, ссылки футера.
- Страница отписки по токену и заголовок List-Unsubscribe.
- Webhook наружу со всеми событиями, чтобы магазин получал их без опроса.

## Прокси-домен для трекинга

Sendry наружу не светим. Все адреса, по которым ходит получатель письма, ведут на отдельный
публичный домен со своим бэкендом. Он принимает запрос, скрыто передаёт его в Sendry и
одновременно делает то, что ждёт пользователь.

- Через прокси-домен идут: ссылки с трекингом кликов, пиксель открытия, страница и POST-эндпоинт отписки, List-Unsubscribe.
- Клик: прокси отдаёт пользователю редирект на целевую ссылку, не дожидаясь ответа Sendry, и передаёт в Sendry событие с исходным User-Agent и IP пользователя.
- Пиксель: прокси сразу отдаёт картинку 1x1 и передаёт событие в Sendry.
- Отписка: страница живёт на прокси, подтверждение уходит в Sendry.
- В Sendry все трекинговые адреса генерируются с базовым URL прокси-домена, настраивается в конфигурации.
- Контракт прокси и Sendry: внутренний API событий (open, click, unsubscribe) с авторизацией и передачей оригинальных User-Agent и IP.
- HMAC-подпись ссылки проверяется дважды. Прокси проверяет первым, потому что он публичный и не должен редиректить и слать события по поддельным адресам. Sendry проверяет повторно, потому что может быть раскрыт и не должен доверять входящим событиям. Секрет подписи общий, выдаётся прокси из конфигурации Sendry.
- Прокси не хранит состояние: при недоступности Sendry пользователя всё равно редиректит, событие кладёт в очередь на повтор.
- Если нужно, прокси может быть несколько, по одному на домен отправки.

Заметка: домен обратного адреса для VERP тоже публичный, его MX должен указывать на сервер,
принимающий почту. Либо прокси принимает SMTP и пересылает в Sendry, либо под bounce
выделяется отдельный хост. Решить вместе с контрактом прокси.

## Доставка и ошибки

- Классификация синхронных ошибок по типам и список email по каждому типу уже сделаны (`internal/web/stats/errors.go`, страница задания отправки). Остаётся перенести классификатор в MTA или в общий пакет, чтобы тип писался в событие, а не вычислялся в панели.
- VERP: уникальный обратный адрес на каждое письмо, чтобы асинхронный bounce можно было привязать к письму и получателю.
- Приём входящих DSN на SMTP Sendry и их разбор: извлечение кода ошибки и адреса, прогон через тот же классификатор, событие bounce.
- FBL для Mail.ru, Яндекса, Gmail Postmaster для приёма жалоб.

## Статистика кампании и Stats API

- Метрики: выбрано, отправлено, доставлено, недоставлено, процент доставки, уникальные и общие открытия, Open Rate, уникальные и общие клики, CTR, CTOR, отписки и их процент, жалобы и их процент.
- Карта кликов: по каждому элементу уникальные пользователи и общее число кликов, с отображением поверх превью письма.
- Динамика доставок, открытий, кликов по дням и по часам.
- Разбор User-Agent: мобильные и ПК, ОС, браузер, почтовый клиент.
- Доставляемость в разрезе почтовых доменов: Gmail, Yandex, Mail.ru, Outlook, прочие.
- GeoIP по открытиям с пометкой прокси Apple и Gmail, VPN, ботов.
- API статистики кампании, чтобы магазин читал всё перечисленное.

## A/B-тесты

- Тестируемый элемент: тема, прехедер, баннер, CTA, вёрстка, время отправки.
- Настройки: доля аудитории в тесте, длительность теста, метрика победителя.
- Автовыбор победителя по Open Rate, CTR или CTOR и автодосыл остатку базы.
- Приём победителя от магазина по API, когда критерий денежный.
- Хранение результатов по каждому варианту с отметкой победителя. Сравнение кампаний между собой по доставляемости, OR, CTR, CTOR, отпискам, жалобам.

## Конструктор писем

- Закрыт почти полностью. Проверить копирование кампании, превью мобильной и десктопной версии, условные блоки под персональные товары из переменных шаблона.
